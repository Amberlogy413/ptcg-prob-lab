# 10. 對戰沙盤 — 真回合制遊戲設計

> 本文件記錄「對戰」工作區由自由沙盤重建為**忠實回合制 Pokémon TCG 遊戲**的設計
> (擁有者要求 2026-06-17:要似 PTCG Live / tcgmasters.net)。寫法為書面語
> (zh-Hant);程式識別碼與註解維持英文。

## 10.1 目標與硬性約束

目標:讓「對戰」工作區玩起來像一場真實的回合制對局——**卡牌的類型決定你能對它
做甚麼**——同時保留即時精確抽牌概率 HUD(本產品的賣點)。

硬性約束(不可妥協):

1. **IP 安全。** tcgmasters.net 使用官方卡圖;本產品**一律不可**使用任何官方
   寶可夢卡圖、標誌或卡面掃描。我們以**自家原創文字卡面**(`CardVisual`)呈現,
   做到遊戲感而不觸碰版權。
2. **精確數學核心受保護。** `src/lib/prob/` 為位元級保護、禁用浮點;對戰不得引用
   或改動它。抽牌概率經 `src/state/battle.ts` 的 `computeDrawOdds` 橋接。
3. **只信真實資料。** 卡牌效果一律取自已核實的目錄(`category` / `stage` /
   `trainerType` / `energyType` / `attacks` / `weaknesses` / `retreat`),**絕不
   猜度**;無法確定的效果保持手動,並誠實標示。
4. **全客戶端、暫態。** 對戰盤面不持久化(刮擦板);以種子洗牌可重現。

## 10.2 狀態模型(`src/state/battleStore.ts`)

* **散牌堆(`Pile`)**:`deck` / `hand` / `discard` / `prizes` / `lostzone`,
  各為一個有序的 `BattleCard[]`。
* **場上寶可夢為一個「單位」(`InPlay`)**:

  ```
  InPlay = {
    uid           // 穩定單位 id = 最底寶可夢的 iid(跨進化不變)
    card          // 當前最上層寶可夢
    under[]       // 下層進化階(由底至上)
    energy[]      // 附著能量
    tools[]       // 附著工具
    damage        // 已受傷害(HP 損失);damage ≥ hp 即被擊倒
    playedTurn    // 上場/進化的回合(召喚失調規則)
    status[]      // 特殊狀態(只在戰鬥場有意義)
  }
  ```

* **玩家盤面(`PlayerBoard`)**:五個散牌堆 + `active: InPlay | null` +
  `bench: InPlay[]`(上限 `MAX_BENCH = 5`)+ `stadium: BattleCard | null`。
* **每回合旗標**(`endTurn` 時重設):`turnSupporterUsed` / `turnEnergyAttached`
  / `turnStadiumPlayed` / `turnRetreated`。
* **`everInPlay: {p1,p2}`**:每方是否曾有寶可夢上場——令「場上無寶可夢即落敗」
  只在被清場後觸發,**不會在分散的手動擺盤階段誤判**。

**卡牌守恆是神聖的**:任何 move / 進化 / 擊倒 / 退場 / 收回 / 附著 / 復原都不得
重複或遺失任何卡牌實例(`iid`)。

## 10.3 卡牌類型 → 動作對照

`PlayKind` 由 `src/state/battlePlay.ts` 的 `playKindOf(card)` 從真實目錄推導;
無目錄對應時按 `section` 退而求其次(訓練家一律退為 `item`,**永遠上不到場**)。

| 類型 | 動作 | 去向 | 每回合限制 |
|---|---|---|---|
| 基礎寶可夢 | 上戰鬥場 / 上備戰 | `active`(空時)/ `bench`(≤5) | — |
| 進化寶可夢 | 進化 | 疊到場上對應單位之上 | 每隻每回合一次(暫不硬性檢查名稱) |
| 基本/特殊能量 | 附能量 | 附到場上寶可夢 | **1 次** |
| 支援者 | 使用 | 結算後入棄牌 | **1 張** + 先手第一回合禁用 |
| 物品 | 使用 | 入棄牌 | — |
| 工具 | 裝備 | 附到場上寶可夢 | — |
| 競技場 | 放置 | `stadium`(換走舊張入棄牌) | **1 張** |

> **進化名稱不硬性比對。** 卡名跨 zh/ja/en 不可靠,硬性檢查下層名稱會誤拒合法
> 進化;故與「不自動執行 ACE SPEC」同一誠實立場——介面提示下層名,由玩家確認。

## 10.4 回合結構

* 視角:**底 = 當前玩家**(手牌可操作),頂 = 對手(鏡像、手牌隱藏)。
  「結束回合」**翻轉視角**——即 tcgmasters「自己打兩邊」的玩法。
* **回合開始抽牌**:`endTurn` 為輪到的玩家自動抽 1 張(空牌庫不抽——抽不到牌的
  落敗以警告呈現,不自動判)。先手玩家的第一回合抽牌在 `begin()` 完成(現行規則:
  先手亦抽)。
* **先手第一回合限制**:不可攻擊、不可打支援者(`battle.atk.firstTurnNoAttack`
  / `battle.fx.firstTurnNoSupporter`)。

## 10.5 攻擊(`src/state/battleAttack.ts`)

純函數、可測試:

* `canPayCost(attached, cost)`:**屬性感知付費**——每個非無色符號需對應元素的
  能量(或一張 wildcard);無色由餘下能量支付;特殊/未知能量為**誠實的
  wildcard**(不捏造其屬性)。
* `finalDamage(attacker, defender, base)`:依**防守方**對**攻擊方屬性**的弱點
  (預設 ×2)/ 抵抗調整;`baseDamage` 取印刷底值。**注意誠實邊界**:「120+」「20×」
  這類變動傷害只取**印刷底值**(「+」/「×」修正不在資料內,無法精確還原),
  故對戰沙盤對這類攻擊顯示的傷害/擊倒只屬**近似**,並非精確結算
  (`isVariableDamage` 可判別;詳見 docs/11 §5)。
* `prizeValue(card)`:ex / 超級 / V / VSTAR = 2,VMAX = 3,其餘 = 1。

流程(`BattleView.doAttack`):核對回合/目標/付費 → 對對手戰鬥場施加傷害 →
若擊倒則 `knockOut`(單位連附著卡入棄牌)+ `takePrize` → **攻擊結束回合**。

## 10.6 特殊狀態與回合間結算

`status[]`:中毒 / 灼傷 / 睡眠 / 混亂 / 麻痺,逐單位切換、卡面以 chip 顯示。
`endTurn` 的回合間結算施加**確定性**傷害:中毒 +10、灼傷 +20;睡眠/混亂/麻痺的
解除需擲銀 → 交由玩家(誠實)。狀態在退場或進化時清除。

## 10.7 勝負判定(`gameResult`,純函數)

* 取得全部 6 張獎賞卡 → 勝。
* 對手場上無寶可夢(經 `everInPlay` 守衛,避免擺盤期誤判)→ 勝。
* 牌庫已空 → 以警告呈現(抽牌為手動,不自動判負)。

## 10.8 概率 HUD 誠實性

`DrawHud` 以 `computeDrawOdds(deckSize, targetCount, draws)` 計算「接下來抽 n
張、至少抽中目標」的精確超幾何概率,**前提是牌庫已洗勻、永遠由頂抽**。因此:

* 任何把牌放到牌庫底/重排/偷看牌庫頂的機制都會令此數**靜默地錯**——必須避免或
  明確標註。`奇樹`(Iono,放回牌庫下方)因此**從不自動結算**。
* `shuffleHandUnderDeck` 只由玩家手動觸發,且 HUD 附註提醒「先洗牌庫回復均勻」。

## 10.9 復原(Undo)

視角層的歷史堆疊:透過 `useBattleStore.subscribe` 在每次行動**前**快照狀態
(上限 40,新開局/重揀牌組時清空)。撳一下即還原手動盤面的誤觸;堆疊為空時掣禁用。
